# Patient Timeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the ggplot2-based Patient Timeline tool in the repo and flip its `winviz.html` card from "coming soon" to "available", matching the pattern already used by the other five available tools.

**Architecture:** One self-contained R script (`tools/patient-timeline/patient_timeline_template.R`) standardizes multiple SDTM domains (AE/EX/CM/LB) into a common `USUBJID | Time | Form | tooltip` shape, stacks them, and plots on a shared time axis faceted by subject. It outputs a PNG (committed as `preview.png`) and an optional plotly HTML (not committed, matches repo convention). No tests framework exists in this repo for R scripts or the static site — verification is: run the script and confirm console/output, and diff the new card block against a sibling "available" card for structural consistency.

**Tech Stack:** R, dplyr, ggplot2, plotly (optional), htmlwidgets (optional). Static HTML/CSS already defined in `winviz.html` — no new front-end code.

## Global Constraints

- Script filename pattern: `<name>_template.R` (matches `swimming_template.R`, `spider_template.R`, `waterfall_template.R`, `km_template.R`).
- Only `<name>_template.R` and `preview.png` get committed per tool folder — no RTF, no demo HTML, no `.rds`/data artifacts (matches `swimming-plot`/`spider-plot`/`waterfall-plot`/`km-curve`, not the more elaborate `forest-plot`).
- Card structure for an "available" tool (see `winviz.html:503-534`, the KM Curve card, as the canonical pattern):
  `div.viz-card.available[data-category="figure"]` → `div.card-preview > img.preview-img[onclick="openLightbox(this.src)"]` → `div.card-body` with `h3.card-title`, `p.card-desc`, `div.card-footer > div.card-tech > span.tech-pill` (one per tech) and `div.card-actions > a.btn-code[target="_blank"]`.
- Source of truth for the R script content is the finalized, already-validated version at
  `/private/tmp/claude-501/-Users-winkle---Projects-R-Winkode/f28a8c2c-d14f-454e-9a52-d3c9205c99ed/scratchpad/patient_timeline_template.R` — do not re-derive it; every design decision in it (facet strip-left fix, plotly annotation post-processing, `scale_y_discrete` axis-order fix, `interactive()` guard) was already debugged and confirmed working in the conversation that produced this plan.
